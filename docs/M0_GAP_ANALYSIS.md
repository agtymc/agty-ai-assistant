# Сверка текущего состояния с M0

Дата: 18 сентября 2026. Источник требований: `docs/TECHNICAL_SPECIFICATION.md`, разделы 5, 5.1, 5.2 и 12.

## Текущий статус

Версия 0.11.0 закрывает рабочий чат Codex CLI, историю сессий, выбор модели и уровня рассуждения, базовый режим чтения/редактирования, slash-команды, оформление чата, ссылки на исходники, базовый безопасный контекст активного редактора и упаковку устанавливаемого ZIP.

Проект всё ещё не является полным M0 из ТЗ. Сейчас он ближе к E1: есть сквозной чат, адаптер Codex, настройки, история и первый контролируемый ручной контекст, но нет полноценного автоподбора контекста, diff-review, editor actions, completion, Git-сообщений и шаблонов.

## Следующая очередь работ

1. **Документировать фактическую платформу 0.11.x.** ТЗ предлагает Kotlin и целевую 2026.2, а текущая реализация использует Java и IntelliJ IDEA 2025.3. Нужно закрепить это как текущее решение E0 или обновить допущения ТЗ.
2. **Довести контекст до M0.** Добавить символы, диагностики по нескольким файлам, выбранные фрагменты diff и бюджетирование по модели.
3. **ChangeSet и diff-review.** Добавить выборочное принятие hunks, автоматическое извлечение diff из ответа модели, Undo и форматирование изменённых участков.
4. **Editor actions.** Добавить контекстные действия над выделением: объяснить, найти проблемы, предложить исправление. Сначала без автоприменения, затем через ChangeSet.
5. **Git commit message.** Использовать выбранный Git diff как контролируемый ContextItem и возвращать редактируемое сообщение.
6. **Ollama/OpenAI-compatible provider.** Делать после ProviderCapabilities и ContextPolicy, чтобы локальный режим и отсутствие remote fallback соответствовали FR-01/FR-12.
7. **Inline completion.** Выделить отдельный канал запроса с debounce и отменой устаревших ответов; не смешивать с chat-сессиями.

## Ближайший технический спринт

Цель: заложить безопасную основу контекста без изменения пользовательского сценария чата.

Результаты:

- пакет `security` или `context` с политикой доступа к файлам проекта;
- чтение `.noai`, `.aiignore`, `.gitignore` и стандартных build-каталогов;
- тесты на path traversal, symlink, исключённые файлы и проектный корень;
- интеграция политики перед запуском Codex-запроса;
- README с ограничениями: что фильтрует плагин, а что остаётся ответственностью внешнего Codex CLI/MCP.

После этого можно безопаснее переходить к ручному контексту и diff-review.
