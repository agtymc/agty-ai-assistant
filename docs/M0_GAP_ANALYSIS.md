# Сверка текущего состояния с M0

Дата: 18 сентября 2026. Источник требований: `docs/TECHNICAL_SPECIFICATION.md`, разделы 5, 5.1, 5.2 и 12.

## Текущий статус

Версия 0.10.2 закрывает рабочий чат Codex CLI, историю сессий, выбор модели и уровня рассуждения, базовый режим чтения/редактирования, slash-команды, оформление чата, ссылки на исходники и упаковку устанавливаемого ZIP.

Проект всё ещё не является полным M0 из ТЗ. Сейчас он ближе к E1: есть сквозной чат, адаптер Codex, настройки и история, но нет полноценного контролируемого контекста, diff-review, editor actions, completion, Git-сообщений и шаблонов.

## Следующая очередь работ

1. **Документировать фактическую платформу 0.10.x.** ТЗ предлагает Kotlin и целевую 2026.2, а текущая реализация использует Java и IntelliJ IDEA 2025.3. Нужно закрепить это как текущее решение E0 или обновить допущения ТЗ.
2. **ContextPolicy / ProjectAccessPolicy.** Вынести проверку `.noai`, `.aiignore`, `.gitignore`, бинарных файлов, build-каталогов, symlink и path traversal в отдельный слой. Это база для FR-03, FR-04, FR-08 и FR-12.
3. **ContextItem и ручной предпросмотр контекста.** Начать с текущего файла, выделения и несохранённого документа; показать список источников до отправки и дать отключить их для запроса.
4. **ChangeSet и diff-review.** Перехватывать/представлять предлагаемые изменения как операции с исходным хешем, показывать diff, применять только выбранные фрагменты, блокировать конфликт с новой пользовательской правкой.
5. **Editor actions.** Добавить контекстные действия над выделением: объяснить, найти проблемы, предложить исправление. Сначала без автоприменения, затем через ChangeSet.
6. **Git commit message.** Использовать выбранный Git diff как контролируемый ContextItem и возвращать редактируемое сообщение.
7. **Ollama/OpenAI-compatible provider.** Делать после ProviderCapabilities и ContextPolicy, чтобы локальный режим и отсутствие remote fallback соответствовали FR-01/FR-12.
8. **Inline completion.** Выделить отдельный канал запроса с debounce и отменой устаревших ответов; не смешивать с chat-сессиями.

## Ближайший технический спринт

Цель: заложить безопасную основу контекста без изменения пользовательского сценария чата.

Результаты:

- пакет `security` или `context` с политикой доступа к файлам проекта;
- чтение `.noai`, `.aiignore`, `.gitignore` и стандартных build-каталогов;
- тесты на path traversal, symlink, исключённые файлы и проектный корень;
- интеграция политики перед запуском Codex-запроса;
- README с ограничениями: что фильтрует плагин, а что остаётся ответственностью внешнего Codex CLI/MCP.

После этого можно безопаснее переходить к ручному контексту и diff-review.
