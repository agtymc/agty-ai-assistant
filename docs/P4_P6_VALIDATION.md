# Проверки интеграции Codex 0.14.0

17 ноября 2026 года. Этот отчёт заменяет перечень незавершённых возможностей в историческом P1_P3_VALIDATION.md. Исходные пользовательские изменения не сбрасывались; рабочая ветка и индекс сохраняются.

## Локальная приёмка

Окружение: Linux x86_64, JDK 21 для production, IDEA/JBR 2025.3, IU-253.28294.334, Codex CLI 0.169.0.

```bash
python3 scripts/gradle_with_proxy.py test buildPlugin verifyPluginStructure verifyPlugin \
  -PrealCodexSmoke=true -PjcefSmoke=true --console=plain
python3 scripts/generate_command_docs.py
git diff --check
```

- 122 теста, 0 падений, ошибок и пропусков в полном прогоне с обоими smoke-флагами.
- `buildPlugin`, `verifyPluginStructure`, `verifyPlugin`: BUILD SUCCESSFUL. Plugin Verifier: **Compatible** с IU-253.28294.334; отмечены обращения к экспериментальному API платформы `WriteIntentReadAction`. Целевой диапазон остаётся 253.*.
- Verifier выдал HTTP 451 при попытке загрузить сторонние необязательные плагины IDE (CLion Radler/Go Template); итоговый вердикт плагина — Compatible. Эти предупреждения не скрыты настройками failureLevel.
- Установочный ZIP: `build/distributions/agty-ai-assistant-0.14.0.zip`.
- Реальный Codex: read-only запрос в отдельном временном каталоге, ожидаемый публичный ответ, завершение turn, неизменность контрольного файла и отсутствие новых файлов. Использовано существующее хранилище авторизации, секреты не выводились.
- Настоящий JCEF/JBR: обновление DOM, сохранение выбранного текста до снятия выделения, сохранение неизменённых узлов; 1000 карточек (~700 KiB текстовых данных) отображаются в пределах контрольного таймаута 15 секунд. Это smoke-порог, а не обещание производительности на любом компьютере.
- Swing: границы основных элементов при 320/360/480 логических px и масштабе 100/150/200%, светлая Metal и тёмная Darcula LAF. 18 снимков в `build/reports/screenshots/`; дополнительно chat-320.png. Автоматическая геометрия не подменяет ручную оценку удобства.

## Сквозные и регрессионные сценарии

- RPC по ID с перемежающимися ответами, EOF/close, независимые подписчики; две нативные задачи с одинаковыми item ID, адресная отмена одной и сохранение второй.
- Восстановление исходного turn без второго `turn/start`; задача переживает переключение, dispose и открытие панели.
- Сериализация записи по real cwd, параллельность независимых каталогов, отмена queued задачи, остановка принадлежащих проекту процессов. Очередь читает актуальный native thread ID и сохраняет новый несвязанный черновик.
- Несколько ожидающих подтверждений, ответ ровно один раз, resolution другим клиентом, отказ после resolution. Серверный availableDecisions ограничивает UI; постоянные правила передаются без расширения исходного предложения.
- Вопросы, секретные поля, primitive MCP forms, enums, multiple-choice arrays, числовые/строковые ограничения и форматы; неизвестная схема не принимается. URL-elicitation требует отдельного явного ответа после браузера.
- Native review и compaction не превращаются в обычный `turn/start`; observe не переопределяет cwd/политику и не создаёт новый turn. Guardian retry адаптирует только поля исходного отказа.
- Постраничные элементы истории с повторяющимися item ID разных turn, финальные снимки без дублирования, неизвестные элементы, публичные summaries без raw reasoning. Большие результаты и изображения проверяются по SHA-256, traversal и повреждение блокируются.
- Полный fake App Server сценарий: исходная незакоммиченная пользовательская строка → явное подтверждение → нативное изменение файла → карточка изменений → зафиксированная итоговая версия → проверяемый откат к пользовательской строке.
- Создание/удаление/переименование и цепочка rename с занятым целевым путём, CRLF/Unicode/no-final-newline, hunk rollback, повреждённая база и поздние пользовательские правки. Неподтверждённые shell/binary изменения видны без права автоматического отката.
- Staged/unstaged/untracked, unborn Git, пути с пробелами; создание отдельного worktree без потери грязного исходного дерева.
- Обновление VFS во время fileChange и на завершении/ошибке/отмене; нативный reload документа не считается пользовательским редактированием, ручной ввод блокирует автоматический откат (проверено на реальном FileDocumentManager).
- XML-миграция прежней истории/черновиков/выбора провайдера, отдельный доступный архив локальных сообщений после перечитывания нативной истории, сохранение прежних прав и Auto только для нового проекта.
- 63 канонические статьи (55 обработчиков, 8 явно отложенных по границам плана), не менее двух примеров со сценариями, корректные aliases/related, offline help, рабочая последовательность, неизвестные команды сохраняют черновик. Копирование/вставка не запускают действия.

## Платформы и границы проверки

CI выполняет `test buildPlugin verifyPluginStructure verifyPlugin`, проверяет воспроизводимость Markdown и сохраняет ZIP/отчёты для Linux, Windows и macOS. На Linux дополнительно выполняется полный набор с нативным JCEF под Xvfb. Результаты удалённой матрицы и проверенный commit доступны в [Checks draft PR #1](https://github.com/agtymc/agty-ai-assistant/pull/1/checks). Прогон [44075010630](https://github.com/agtymc/agty-ai-assistant/actions/runs/44075010630) завершился успешно на трёх ОС; после финальных правок выполняется контрольный прогон того же набора. Реальный CLI smoke включён локально; CI без авторизации пропускает его явно.

Первый прогон выявил и позволил исправить alias-пути (`/var`/`/private/var`, Windows 8.3), UTF-8 вывода Java fixtures и зависимость тестового worktree от `core.autocrlf`. Повторный Linux-прогон выявил непригодность кэширования распакованного IDE/JBR в immutable Gradle transforms: CI теперь кэширует только скачанные modules-2/wrapper, пересоздавая распакованные SDK из архивов.

Не утверждается совместимость с другими CLI/ветками IDEA. Наличие обработчика интеграции не гарантирует наличие у аккаунта skills/apps/Daybreak или настроенного внешнего MCP-сервера. Проверка не меняла реальную глобальную конфигурацию пользователя и не устанавливала сторонние плагины. Реальный вход/выход OAuth не выполнялся поверх действующей авторизации; RPC и явные пользовательские действия реализованы отдельно от read-only smoke.

Надёжный откат не выводится из Git HEAD и не допускается без сохранённой базы. Снимки ограничены 256 MiB/100000 файлов, живут до закрытия проекта; исключённые/бинарные или неподтверждённые операции могут требовать ручного сравнения. Сохранность внешних одновременно пишущих процессов не обеспечивается атомарной файловой транзакцией ОС; текущие версии повторно проверяются перед каждой операцией, уже обращённые операции восстанавливаются при последующей ошибке, когда это безопасно.
