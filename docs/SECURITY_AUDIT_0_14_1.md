# Аудит безопасности и сохранности данных — 0.14.1

Дата: 17 ноября 2026 года. Проверены фактические исходники рабочего дерева после реализации P0–P6, включая новые изменения Guardian/approve. Отчёт P4_P6_VALIDATION.md относится к предыдущему снимку 0.14.0 и не подтверждает отсутствие перечисленных ниже дефектов.

Аудит выявил реальные ошибки. Они исправлены с регрессионными сценариями. Изменения пользователя, локальная master и индекс сохранены; исходное дерево дополнительно сохранено в закрытом локальном резервном архиве. Содержимое пользовательских проектов и секреты не отправлялись во внешние сканеры: OSV получил только имена и версии пяти библиотек.

  -PrealCodexSmoke=true -PjcefSmoke=true --console=plain

Локально: **186 тестов, 185 passed, 0 failures/errors, 1 Windows-only пропуск** (ADS на Linux неприменим). Оба opt-in smoke выполнены. `test buildPlugin verifyPluginStructure verifyPlugin`: BUILD SUCCESSFUL; Plugin Verifier — **Compatible** с IU-253.28294.334, 16 обращений к экспериментальному WriteIntentReadAction. Проверка структуры и ZIP проходит. Verifier сообщает HTTP 451 для необязательных сторонних плагинов IDE; это не скрывается настройками failureLevel.

Матрица Linux/Windows/macOS выполняется тем же workflow для проверяемого commit; точный commit и результаты доступны в [Checks PR #1](https://github.com/agtymc/agty-ai-assistant/pull/1/checks). CI не имеет пользовательской авторизации и явно пропускает реальный CLI smoke; Linux отдельно запускает настоящий JCEF. Установочный файл: `build/distributions/agty-ai-assistant-0.14.1.zip`. Реальный CLI использует отдельный временный каталог с контрольным файлом и read-only запросом без инструментов; настоящий проект модели не передаётся. JCEF проверяется настоящим JBR/CEF, включая стабильность DOM/выделения и 1000 карточек. Swing проверяется на ширинах 320/360/480 и масштабах 100/150/200% в двух темах.

Для пяти фактически упакованных сторонних Maven JAR выполнен запрос к [OSV API](https://google.github.io/osv.dev/api/): gson 2.11.0, commonmark и два расширения 0.24.0, error_prone_annotations 2.27.0. Совпадающих опубликованных advisories не получено; [машинный результат](security/dependency-audit-0.14.1.json). Отсутствие записи в базе не доказывает отсутствие неизвестных уязвимостей. IDE/JBR и инструменты сборки этим запросом не покрыты. Поиск типичных private-key/token форматов в исходниках и скриптах не нашёл совпадений; это не замена классификации произвольных пользовательских данных.

## Границы гарантий

- Контекстные `.aiignore`/`.gitignore` не ограничивают инструменты самого Codex. Read-only и Auto ограничивают запись, но не обещают полной изоляции чтения вне cwd. Полный доступ сознательно снимает sandbox. Инструменты могут прочитать чувствительные данные и передать их выбранной модели в рамках предоставленных прав.
- История, пользовательские тексты, результаты инструментов и снимки хранятся локально без шифрования плагином. Штатные OAuth-данные и ответы secret-полей не добавляются в историю, но введённый пользователем секрет в обычном сообщении или в выводе команды сам по себе не распознаётся как секрет. OS-пользователь и доверенный системный каталог IDEA остаются границей доверия.
- Проверка хеша перед атомарной заменой не является атомарной compare-and-swap транзакцией файловой системы. Внешний процесс того же пользователя всё ещё может изменить файл между последней проверкой и записью. При зафиксированном конфликте автоматический откат запрещается; Git reset --hard не используется.
- Перенос access metadata проверяет owner/group/mode и POSIX/macOS/Windows ACL, а не произвольную политику ОС. ACL/xattr API и права текущего OS-пользователя должны позволять достоверное чтение/перенос; иначе автоматическая замена запрещается. SELinux labels сохраняются как xattrs; невозможность их переноса приводит к отказу. Произвольные политики ОС и файловые системы требуют отдельной проверки администратора.
- Консервативный ручной импорт поддерживает только create/modify UTF-8 текста до 16 MiB на файл, 64 MiB суммарно. Delete/rename/mode/binary не притворяются обычной записью текста. Для atomic replace/create требуется поддержка файловой системы; иначе исходник сохраняется и операция завершается ошибкой.
- Снимки native задач ограничены 256 MiB/100000 файлов и живут до закрытия проекта. Неподтверждённые shell-изменения, неполные базы и неоднозначные rename не дают права на автоматический откат. Не гарантируется сохранение снимков после аварии ОС или очистки временных файлов.
- При неоднозначном запуске/остановке закрывается общий процесс плагина; другие его чаты могут прерваться и восстанавливают только наблюдение. Процессы сторонних клиентов не выбираются по имени и не завершаются.
- Чтение Git отключает clean/process filters и не рекурсирует в submodules: сравниваются raw bytes. Для LFS/пользовательских преобразований это может отличаться от обычного git diff с включёнными helpers. Submodule проверяется явно с собственным cwd.
- Реальные OAuth logout/login, установка стороннего плагина, изменения глобальной конфигурации, произвольные внешние MCP/apps и административные настройки Windows не выполнялись над аккаунтом пользователя. Их RPC/валидация проверяются fake App Server и модульными сценариями; это не сертификация внешней интеграции.
- Подтверждается только проверенный контракт CLI 0.169.0 / IDEA 253. Автоматические тесты не доказывают отсутствие всех возможных ошибок и не заменяют ручную оценку удобства интерфейса.
