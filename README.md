# AGTY AI Assistant

Плагин IntelliJ IDEA с Markdown-чатом и подключаемыми AI-провайдерами. Текущая рабочая интеграция — Codex CLI; следующая планируемая интеграция — Ollama.

Лицензия: Apache-2.0.

## Возможности версии 0.10

- **Enter** отправляет сообщение, **Shift+Enter** вставляет новую строку; Ctrl+Enter также поддерживается.
- Markdown: заголовки, списки, выделение, цитаты, таблицы и блоки кода с подсветкой по цветовой схеме IDE. Неизвестные языки отображаются обычным текстом.
- В коде сохраняются переводы строк и отступы; длинные строки переносятся по ширине чата. Табуляция отображается с шагом 4 пробела, при копировании сохраняется оригинал.
- **+ Новый чат** создаёт отдельный диалог; меню **Чаты** переключает сессии текущего проекта. Последняя выбранная сессия восстанавливается при открытии проекта.
- Копирование сообщения в исходном Markdown или отдельного блока кода.
- Ссылки на исходники открывают редактор на нужной строке; обычные HTTP(S)-ссылки открываются в браузере.
- Раскрывающиеся карточки хода работы: пояснения, команды, поиск, планы и инструменты; события с одним ID обновляют карточку.
- Индикатор выполнения, текущий этап и время запроса; остановка и новый диалог.
- Автопрокрутка, пока пользователь читает конец ленты; при прокрутке вверх позиция сохраняется.
- Путь к Codex или исполняемой обёртке задаётся в настройках; результат проверки виден при открытом окне настроек.

Интерфейс использует общий контракт `ChatProvider` / `ChatEvent`; в этой версии подключён только Codex. Добавление другого провайдера требует адаптера, а не нового рендерера чата. Это ещё не полный набор возможностей из [ТЗ](docs/TECHNICAL_SPECIFICATION.md).

## Сессии проекта

Меню **Чаты** содержит список сессий с названием, провайдером и UID, создание нового чата, обновление списка Codex, открытие по UID, переименование и копирование UID. Название текущей сессии и короткий UID видны над полем ввода; полный UID — в подсказке. История читается через `codex app-server` с проверкой каталога проекта. Архивные сессии не включаются в список.

**+ Новый чат** создаёт локальный черновик с уникальным идентификатором. Настоящий UID Codex появляется при первом запросе; последующие запросы продолжают этот thread через `app-server`. Заголовок обновляется по первому вопросу, ручное переименование сохраняется. Старые диалоги версии 0.3 остаются доступными; при следующем запросе они создадут сессию Codex с переданным старым контекстом.

Последняя выбранная сессия, история отображения и черновики восстанавливаются при открытии проекта. При переключении выполняющийся запрос останавливается. Codex самостоятельно хранит нативный контекст, включая уже записанные части прерванных запросов. Для перечитывания истории выберите сессию в меню или откройте её по UID.

## Выбор LLM

Под полем ввода расположен выбор **LLM / модели**. Доступные модели Codex загружаются из выбранного CLI и отображаются как **Codex · название модели**. Выбор модели сохраняется для текущей сессии и применяется со следующего сообщения. При смене модели Codex создаёт ответвление диалога с новым UID и сохранённой историей; старый UID остаётся доступен через список сессий. Уже существующие сессии ответвляются при первом запросе после обновления. Черновик сохраняется. Без явного выбора модели отправка заблокирована. Глобальная конфигурация CLI не изменяется. Во время запроса выбор заблокирован.
Перед отправкой в Codex требуется явный выбор модели. Плагин проверяет доступность выбранной модели и уровня рассуждения через `model/list`, затем сверяет модель, подтверждённую ответом `thread/start` / `thread/resume`, до запуска хода. Если сервер возвращает другую модель или не подтверждает выбор, запрос не отправляется. При событии `model/rerouted` на другую модель работа останавливается; предупреждение показывает исходную и целевую модели. Эти проверки не могут вернуть токены, потраченные до получения события перенаправления.

При смене провайдера открывается его последний выбранный диалог либо создаётся новый. История, UID и черновики разных провайдеров не смешиваются. Последний выбор сохраняется вместе с сессией проекта.

Рядом с LLM расположен выбор **уровня рассуждения** (`low`, `medium`, `high` и другие значения, поддерживаемые выбранной моделью). Список и стандартное значение берутся из Codex. Выбор сохраняется в сессии и действует со следующего сообщения; при смене модели применяется её стандартный уровень. Во время запроса переключатель заблокирован. Для моделей без поддержки настройки он скрыт.

Чтобы добавить другое подключение или конкретную модель, реализуйте `ChatProvider` и зарегистрируйте `ChatProviderRegistry.Choice` со стабильным уникальным `id`, подписью и фабрикой. UI берёт варианты из реестра при создании панели и вызывает фабрику выбранного варианта для отправки. `Session.providerId` определяет владельца истории, `nativeSessionId` содержит непрозрачный ID провайдера; старые `codexId` читаются для совместимости. Импорт внешних сессий пока реализован только для Codex. Не подключённые LLM не показываются как рабочие варианты.

Поле ввода по умолчанию занимает две строки. Высоту можно изменить, потянув за «⋯» над вводом (2–12 строк); она сохраняется в настройках оформления. Стрелки ↑/↓ перебирают отправленные запросы и команды текущей сессии; после последней записи восстанавливается незавершённый черновик. Кнопка остановки появляется только во время запроса.

## Режим доступа и команды

Над вводом расположена кнопка-переключатель **Только чтение / Редактирование**. Повторное нажатие возвращает режим чтения. Выбор сохраняется для проекта и действует со следующего запроса. В режиме записи Codex получает `workspaceWrite` с корнем текущего проекта; в режиме чтения — `readOnly`. Переключатель блокируется во время запроса. После редактирования IDE обновляет файлы. Полный доступ к системе не включается; запросы интерактивного повышения прав не подтверждаются автоматически.

В меню **Чаты → Завершить текущую сессию** диалог сохраняется с пометкой «Завершена» и открывается новый. Завершённый диалог можно снова выбрать в том же меню; историю и UID он сохраняет.

Команды вводятся в поле сообщения или выбираются кнопкой **/** сверху. При наборе `/` появляется список подсказок:

- `/status` — текущая сессия, выбранный режим, модель последнего запроса и полученные счётчики токенов; отдельно запрашиваются конфигурация CLI, тип авторизации, тариф и доступные лимиты Codex.
- `/help` — поддерживаемые команды.
- `/model` — открыть тот же список LLM; `/model ID` — выбрать модель по идентификатору из каталога Codex.
- `/new` — новый чат выбранной LLM.
- `/resume UUID` — открыть существующую сессию Codex проекта; без аргумента открывается меню сессий.
- `/permissions read-only` или `/permissions workspace-write` — переключить режим; без аргумента показать текущий.
- `/stop` — остановить запрос.

Это поддерживаемый набор команд плагина, не полный интерактивный терминал Codex. Неизвестные команды не отправляются модели. Для буквального сообщения, начинающегося с `/`, используйте `//`. Команды не включаются в контекст LLM. Отсутствующие данные `/status` обозначаются как недоступные; токены показываются по последнему полученному событию, а не вычисляются по длине текста.

Для дополнительных провайдеров режим записи требует реализации `ChatProvider.newRequest(sessionId, writeAccess)`; базовый адаптер отклоняет запись, если она не поддерживается.

## Оформление чата

**⚙ → Оформление чата** или **Settings → Tools → AGTY AI Assistant → Оформление чата**:

- Шрифты и размеры текста/кода, расстояние между сообщениями, высота поля ввода.
- Цвета IDE либо собственные цвета фона, текста, сообщений пользователя и ссылок; выбор цвета и сброс оформления.
- Перенос кода, автопрокрутка и показ карточек хода работы.

Изменения применяются ко всем открытым чатам после Apply. Подсветка и фон блоков кода используют цветовую схему редактора IDE. Основной рендерер — JCEF: сообщения пользователя справа, свободная лента ответов и скруглённые блоки кода. Если JCEF недоступен, используется Swing с более простым оформлением. Внешние скрипты, изображения и сетевые подключения из документа чата заблокированы.

Визуальные ориентиры: [JetBrains AI Chat](https://www.jetbrains.com/help/ai-assistant/ai-chat.html) и стили чата локального `org.agty.mtx`. Код и ресурсы MTX не копировались; перенесены принципы компоновки.

## Ссылки на код

Поддерживаются `[метод](src/Main.java#L42)`, `[метод](src/Main.java:42:5)`, абсолютные пути внутри проекта и `file:` URI. Ссылки `src/Main.java#methodName` ищут именованный PSI-элемент; для перегруженных методов используйте точную строку. Имена файлов в inline-коде, например `src/Main.java:42`, также становятся ссылками. Переход по символу может ожидать завершения индексации IDE.

Файлы за пределами проекта, включая обход через symlink, не открываются. Raw HTML экранируется; изображения не загружаются автоматически. JavaScript и командные URL не исполняются. Диаграммы Mermaid и LaTeX пока отображаются как текст/код.

## Установка и настройка

1. Установите Codex CLI и авторизуйтесь командой `codex login` под пользователем, запускающим IDE.
2. В IntelliJ IDEA **2025.3** откройте **Settings → Plugins → ⚙ → Install Plugin from Disk** и выберите `build/distributions/agty-ai-assistant-0.10.2.zip`. Перезапустите IDE при запросе.
3. Откройте **Settings → Tools → AGTY AI Assistant**.
4. Укажите путь к исполняемому файлу, например `/usr/local/bin/codex`, или оставьте `codex`, если он доступен в PATH процесса IDE. Пробелы допускаются; кавычки и аргументы в поле не нужны. Поддерживается `~/`.
5. Нажмите **Проверить Codex**, затем **Apply / OK**. Проверка версии не проверяет авторизацию или доступ к модели.
6. Откройте **View → Tool Windows → AGTY AI Assistant**, напишите запрос и нажмите **Отправить** либо `Enter`; для новой строки используйте `Shift+Enter`.

На Windows нужен исполняемый `codex.exe`, а не npm-обёртка `.cmd`. На Linux/macOS у файла должно быть право исполнения. Если IDE запущена из меню рабочего стола, её PATH может отличаться от PATH терминала: задайте абсолютный путь.

Модель, провайдер и учётные данные берутся из окружения и конфигурации CLI; плагин не запрашивает и не хранит API-ключи. Изменение пути применяется со следующего запроса. Если вход отсутствует или истёк, повторите `codex login` в терминале.

## Поведение и ограничения

Плагин запускает выбранный бинарник с `app-server` и обменивается JSON через stdin/stdout без командной оболочки. Запросы используют `thread/start` / `thread/resume` и `turn/start`. События `item/agentMessage/delta` дополняют текст сообщения чанками; окончательный снимок заменяет накопленный текст без дублирования. Перед первым чанком возможна пауза модели. Отображаются доступные публичные пояснения, команды и изменения файлов; внутренние записи reasoning не выводятся. Нативный контекст хранит Codex. Ошибка или обрыв потока не считаются успешным ответом, остановка завершает управляемый процесс.

Codex может читать проект и обращаться к настроенному провайдеру. Ограничение read-only относится к sandbox CLI: подключённые пользователем MCP-серверы и другие интеграции имеют собственные разрешения. Плагин не обеспечивает фильтрацию `.aiignore` для внешнего процесса и не обещает изоляцию всех его интеграций. Корневой `.noai` блокирует запуск новых запросов. Используйте CLI только в проектах, доступ к которым вы готовы ему предоставить.

Таймаут запроса — 10 минут, лимит вопроса и передаваемого старого контекста — 100 000 символов; размер нативного контекста управляется Codex. Кнопка остановки завершает управляемый процесс и его доступных потомков, частичный ответ остаётся виден; записанный контекст нативной сессии контролирует Codex. Закрытие окна/проекта также отменяет запрос. История, контекст, черновики и последняя выбранная сессия сохраняются локально в `options/agty-chat-sessions.xml` каталога конфигурации IDE, без синхронизации настроек; хранение на стороне провайдера регулируется настройками и условиями провайдера.

Пока нет diff-review перед применением изменений, автодополнения, PSI-контекста и вложений несохранённого редактора. Отправка требует CLI с поддержкой `app-server`, потоковых событий и `turn/start`; каталог моделей использует `model/list`. Текст можно копировать стандартными средствами. Совместимость 2026.2, удалённая разработка и WSL не заявляются; Windows/macOS требуют отдельной проверки. Контракт CLI сверялся с локальным `codex-cli 0.154.0`.

## Разработка

Исходники: `src/main/java/org/agty/aiassistant/{chat,core,settings,ui}`; регистрация расширений: `src/main/resources/META-INF/plugin.xml`; тесты: `src/test/java`. Используются Java 21, Swing, IntelliJ Platform SDK и CommonMark с расширениями таблиц/зачёркивания. Это уточнение первоначального предложения Kotlin в ТЗ.

Требуются JDK 21 для компиляции и JDK 21–25 для Gradle 9.1. Используются Gradle Wrapper и IntelliJ Platform Gradle Plugin 2.19.0. При первой сборке загружаются зависимости и IDE; для уже установленной IDE передайте `-PlocalIdePath=/absolute/path/to/idea`.

```bash
./gradlew test           # тесты парсера, аргументов и жизненного цикла процесса
./gradlew buildPlugin    # ZIP для установки
./gradlew runIde         # отдельная IDE с плагином в sandbox
./gradlew verifyPluginStructure # проверка структуры плагина
```

Например: `./gradlew test buildPlugin -PlocalIdePath=/path/to/idea-2025.3`.

Тесты используют локальный Java-процесс вместо модели, не требуют авторизации и проверяют UTF-8/stdin, раздельные потоки, exit code, отмену, таймаут и ограничение размера события. Регрессионные тесты настроек используют IntelliJ test framework и проверяют результат запуска shell-обёртки внутри модального окна (Linux/macOS). Также проверяются клавиши ввода, безопасный Markdown, ссылки и реальный Swing-рендеринг с подсветкой Java. Запросы к модели в тестах не выполняются. Реальную авторизацию и качество ответа проверяйте вручную в тестовом проекте.

## Ручная проверка перед выпуском

1. Установить ZIP, открыть настройки и выбрать действительный путь с пробелами; выполнить проверку версии.
2. Сохранить настройки, перезапустить IDE и проверить сохранение пути.
3. Отправить вопрос, затем уточнение; убедиться, что учитывается история диалога.
4. Остановить длинный запрос; проверить новый запрос и закрытие проекта во время работы.
5. Проверить отсутствующий бинарник, отсутствие авторизации и проект с `.noai`.
6. Попросить таблицу, Java-код и ссылку на метод; проверить подсветку, копирование и переход к строке.
7. Через меню Чаты обновить список, открыть сессию терминального Codex по UID, проверить историю и продолжение; создать две сессии, переключить их, проверить историю и черновики; перезапустить IDE и проверить последний выбор. Открыть другой проект и проверить изоляцию сессий.
8. Изменить шрифты, цвета и перенос кода; проверить Apply, перезапуск IDE, светлую/тёмную тему и узкую панель.
9. Попросить исследовать проект; раскрыть карточку команды, проверить обновления и таймер, прокрутить историю вверх во время выполнения.

Документация интеграции: [Codex non-interactive mode](https://developers.openai.com/codex/noninteractive), [IntelliJ Platform Gradle Plugin](https://plugins.jetbrains.com/docs/intellij/tools-intellij-platform-gradle-plugin.html).
