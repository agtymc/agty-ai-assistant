# AGTY AI Assistant

Интерфейс Codex внутри IntelliJ IDEA **2025.3 (253)**, Java 21, Linux/Windows/macOS. Версия плагина **0.14.0**, проверенный протокол **Codex CLI 0.169.0**. Плагин использует установленный CLI и его хранилище авторизации; автоматически устанавливать или обновлять CLI не требуется. Лицензия Apache-2.0.

## Установка

1. Установите Codex CLI 0.169.0.
2. В IDEA откройте **Settings → Plugins → Install Plugin from Disk**, выберите `build/distributions/agty-ai-assistant-0.14.0.zip` и перезапустите IDE.
3. В **Settings → Tools → AGTY AI Assistant** укажите бинарник `codex` или абсолютный путь и проверьте версию. На Windows нужен `codex.exe`, а не npm-файл `.cmd`.
4. Откройте **View → Tool Windows → AGTY AI Assistant**. Для входа используйте `/login`: штатная OAuth-страница откроется во внешнем браузере. Ключи в XML настроек и историю плагина не записываются.
5. Выберите модель, добавьте контекст и отправьте запрос. **Enter** отправляет, **Shift+Enter** добавляет строку; Ctrl+Enter также поддерживается.

Другой номер CLI не считается автоматически совместимым: перед выполнением проверяется контракт. PATH процесса IDEA может отличаться от PATH терминала; в этом случае задайте абсолютный путь к бинарнику.

## Работа с задачами

Чаты принадлежат сервису проекта. Переключение чата, скрытие окна и пересоздание панели сохраняют выполнение; индикаторы показывают работу, очередь и ожидание ответа. Кнопка **■** и `/interrupt` останавливают выбранную задачу. Закрытие проекта завершает процессы, запущенные этим плагином, без остановки сторонних клиентов Codex.

Изменяющие задачи одного реального cwd выполняются последовательно. Независимые worktree могут работать параллельно. Во время выполнения Enter предлагает уточнение текущего turn или отправку после успешного завершения. При ошибке/отмене подготовленные сообщения сохраняются для ручной вставки через `/queue`, но автоматически не выполняются. После перезапуска IDEA очередь также требует явной отправки.

История Codex загружается страницами с сохранением команд, инструментов, планов и изменений. Черновики и настройки интерфейса хранятся отдельно. Прежние локальные сообщения при перечитывании Codex сохраняются в меню чатов **«Сохранённая локальная история…»** и включаются в экспорт. При обрыве соединения восстанавливается наблюдение исходного turn; повторный `turn/start` автоматически не отправляется. Выбор модели и effort действует на следующий turn без скрытого fork. Для ответвления используйте `/fork`.

## Контекст и разрешения

Контекст включает явный список файлов, выделений, диагностик, Git diff и локальных изображений. В списке доступны просмотр, удаление и отключение; автоматический контекст редактора можно выключить. Изображения проверяются на принадлежность cwd и поддержку моделью.

Новые проекты используют **Auto**: workspace sandbox и интерактивные подтверждения. Существующие настройки доступа при миграции сохраняются. Доступны чтение, Auto и отдельное явное включение полного доступа. **Plan** управляет планированием независимо от прав доступа. Экспериментальный контракт включается отдельно через `/experimental on`; при активных задачах его переключение запрещено.

Файлы `.noai`, `.aiignore` и `.gitignore` учитываются сборщиком контекста. Эти правила не являются sandbox самого Codex. Метаданные `.git` исключены из автоматического контекста и отката; доступ Codex к Git определяется настоящим sandbox и интерактивными разрешениями сервера. Неподдержанная настройка не переводит запрос в полный доступ.

Подтверждения связываются с конкретным запросом. Диалог показывает только допустимые сервером решения, включая точное постоянное правило выполнения/сети, если оно предложено сервером. Закрытие диалога и истечение времени ничего не разрешают. Вопросы с секретным ответом не сохраняют его в истории. MCP поддерживает типизированные primitive forms, enum/array и URL-elicitation; неизвестные ограничения форм нельзя принять автоматически.

## Изменения и откат

`/diff` открывает отдельные списки **«Изменения задачи»** и **«Рабочее дерево Git»**. Во втором представлены staged, unstaged и untracked. Построчный diff в чате содержит номера строк и `+N/−N`; подробное сравнение открывается в IDEA Diff Viewer. Codex уже изменяет файлы: повторно применять эти изменения не нужно.

Перед изменяющей задачей сохраняются документы её cwd и метка Local History, затем снимок фактических файлов, включая прежние незакоммиченные правки. Откат файла, hunk или задачи проверяет исходные версии, итоговые хеши, атрибуты и пользовательское редактирование. Создание, удаление и переименование обращаются как операции. При последующих правках или недостоверной базе автоматический откат запрещён; доступно сравнение. Изменения shell-команд без подтверждённого происхождения видны, но не присваиваются агенту для автоматического отката. `git reset --hard` не используется.

Снимки отката живут до закрытия проекта. Историческая сессия без локальной базы не даёт права на автоматический откат. Лимиты снимка: 256 MiB и 100 000 файлов; каталоги зависимостей, сборки и метаданные исключены. При неполной базе недостоверные операции остаются доступны для сравнения, без автоматического восстановления.

Старый ручной unified patch сохранён отдельно: **⋯ → Импортировать patch…** и **Откатить ручной patch**. Он не применяется поверх нативных изменений автоматически. Действия редактора «Объяснить / Найти проблемы / Предложить исправление / Рефакторинг / Сгенерировать код» сохранены.

## Команды и справочник

`/help` открывает офлайн-вкладку **«Команды Codex — руководство и примеры»**; `/help review` или `/help /review` выбирает статью. Повторное открытие использует существующую вкладку. Есть поиск по имени, aliases, русским описаниям и сценариям, категории, переходы между статьями и рабочая последовательность. Примеры можно копировать и вставлять в конец черновика; вставка ничего не выполняет.

Каталог, доступность, UI и генерируемый [Markdown-справочник](docs/CODEX_COMMANDS.md) используют один ресурс. Команды ищутся кнопкой `/` или вводом `/`; доступны ↑/↓, Enter, Esc и F1 для справки. Неизвестная команда сохраняет текст и не отправляется модели. Для буквального текста с `/` используйте `//`.

- `/review` запускает native Codex review; `/diff` показывает уже существующие изменения.
- `/new` создаёт чат, `/clear` дополнительно очищает контекст; файлы не откатываются.
- `/resume` открывает существующую историю; `/fork` создаёт явное ответвление.
- `/compact` запускает native compaction; `/recap` просит текстовый итог отдельным запросом.
- `/stop` и `/clean` останавливают фоновые терминалы; `/interrupt` и ■ останавливают текущий turn. Это изменение семантики относительно 0.13.0.
- Plan, goal, очередь, worktree, агенты, OAuth, skills/MCP/apps/plugins/hooks и память управляются через UI/RPC. Глобальные настройки меняются только отдельным явным действием. Скорость и Daybreak доступны по каталогу модели/аккаунта, без повышения sandbox-прав.

Голос, pets, удалённый app-server и терминальные функции `/raw`, `/tui`, `/daemon`, `/title`, `/statusline` явно отложены. Скрытые отладочные команды не включены в обычный список. `/side`/`/btw` адаптированы к независимому чату-fork; `/cd` создаёт чат с новым cwd, сохраняя привязку прежнего нативного thread.

## Отображение

Основной рендерер — JCEF с обновлением отдельных карточек, сохранением выделения и положения прокрутки; Swing используется при недоступном JCEF. Копирование сохраняет исходный Markdown/код. Ссылки `[метод](src/Main.java#L42)` открывают редактор; HTTP(S) — браузер. Ссылки вне cwd и обход через symlink запрещены. Raw HTML экранируется, внешний контент и сетевые подключения из документа ленты заблокированы. Локальные изображения открываются отдельным действием.

Большие завершённые результаты сохраняются целиком в локальном хранилище с проверяемым SHA-256; в ленте находится preview с действием полного просмотра. Протокольная строка ограничена 16 млн символов, накопленный поток — 64 млн; превышение завершает запрос с объяснением, без молчаливого обрезания. Шрифты, цвета, перенос кода и автопрокрутка доступны через **Settings → Tools → AGTY AI Assistant → Оформление чата**.

## Разработка и проверки

JDK 21, Gradle Wrapper:

```bash
./gradlew test buildPlugin verifyPluginStructure verifyPlugin
python3 scripts/generate_command_docs.py
python3 scripts/update_codex_protocol.py
```

При окружении с HTTP(S)_PROXY используйте `python3 scripts/gradle_with_proxy.py test buildPlugin verifyPluginStructure verifyPlugin --console=plain`. Помощник не сохраняет учётные данные proxy.

Проверки с реальным CLI и нативным JCEF включаются явно, используют отдельный временный каталог и требуют установленный совместимый CLI/авторизацию либо JBR с JCEF:

```bash
python3 scripts/gradle_with_proxy.py test -PrealCodexSmoke=true -PjcefSmoke=true
```
